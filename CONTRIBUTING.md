# Contributing

Keep the transformation purpose explicit. Start with an observed user problem,
limit the change, preserve authored artifacts and add focused regression coverage
for deterministic behavior. Run the checks in docs/testing.md. UI changes require
actual browser scenarios and new source-bound captures. Never fabricate reviews or
promote simulated business behavior to production evidence.

Use synthetic public examples only. Do not commit secrets, customer material or
private source briefs. Disclose AI assistance and its extent in contributions.
This initial implementation was authored and tested with an AI coding assistant;
no stakeholder acceptance or live native-adapter execution is implied.

Breaking manifest changes require a schema version and migration story. Preserve
stable IDs. Re-audit the pinned Spec Kit revision before widening compatibility.
